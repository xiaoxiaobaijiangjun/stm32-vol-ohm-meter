# stm32-vol-ohm-meter

基于 STM32F103C8T6 的便携式电压/电阻检测仪，硬件来自一个开源检测板项目（原理图工程和 BOM 归档在 `docs/hardware/`），固件是我的二次开发。

做这个项目的出发点：检修电路时万用表要手动换量程、读数要看小屏幕，而一块专用检测板可以做成"表笔一接、读数直接上屏"——自动识别量程、超限报警、通断蜂鸣，测量结果还能通过串口/BLE 无线上报，方便记录。

## 功能

- 电压测量：0-5V / 5-15V 双量程自动识别，差分测量带正负号
- 电阻测量：0R-1K / 1K-100K 双量程，恒流法和分压法自动切换
- 通断检测：电阻 ≤ 15Ω 连续蜂鸣，超量程显示 OL.
- 表笔反接保护（P-MOS），反接也能测
- 两点校准：每量程一阶修正（y=k·x+b），参数存 Flash 末页，串口控制台操作
- 测量数据经 USART1 上报，接 BLE 模块即可无线传输

## 测量链路设计

信号链：表笔输入 → 分压/恒流网络 → LM358 调理（抬到 1.65V 附近）→ ADC1 七通道扫描 + DMA → 软件两级滤波 → ST7735 TFT 显示。

几个关键取舍：

- **VREFINT 实时校准**。电池供电电压会漂，直接用 ADC 原始值换算读数会跟着漂。用片内 1.21V 基准通道实时算出实际 VREF，每个读数先除以它——供电波动的影响直接消掉，不需要高精度外部基准。
- **恒流源自校准**。电阻档的恒流值不按电阻标称值算，而是由两个基准通道（1.65V 和恒流参考节点）的实测 ADC 值算出来。基准电阻的精度误差被这个做法吸收掉了。
- **两级平均**。DMA 连续采样凑 64 轮累加平均去掉高频噪声，再过 16 点滑动平均稳定显示，刷新率还够。
- **校准参数存 Flash 末页**。magic + 版本 + 4 组 {k,b} + CRC32，读回校验，损坏或超出合理窗口就回退默认恒等参数——校准数据坏了不至于开不了机。

## 引脚

| 外设 | 引脚 | 说明 |
|---|---|---|
| ADC1_IN1-IN6 | PA1-PA6 | 基准/电压×2/电阻×2/恒流参考 |
| SPI1（重映射） | PB3/PB5 | ST7735 TFT（默认引脚被 ADC 占了） |
| MODE 按键 | PB9 | EXTI 下降沿，模式切换 |
| 蜂鸣器 | PA7 | 量程与通断提示 |
| 上报串口 | USART1 | 校准控制台 + 数据上报/BLE |

电源 Type-C 5V 进 LDO 出 3.3V，XD7660 电荷泵产生 -5V 给运放，TL431（0.5%）分压出 1.65V 基准。

## 软件

裸机前后台：`Core/` 是 CubeMX 生成的 HAL 层，`hardware/` 是 LCD 和按键驱动，`middle/` 是滤波和校准，`app/` 是三种模式的页面与测量算法。ADC 在 DMA 中断里累加，凑满 64 轮置标志，主循环取数刷新。

## 编译

Keil MDK 打开 `MDK-ARM/stm32-vol-ohm-meter.uvprojx`（AC5），也可用 STM32CubeIDE 导入。注意 `middle/mid_lcdfont.h`、`hardware/hw_key.c` 含中文字面量，必须保持 GBK 编码，UTF-8 会在 armcc 下报 `missing closing quote`。

## 已知问题

- `lcd_fill` 的参数顺序看起来是 (height, width)，在竖屏行列交换设置下恰好覆盖全屏，不要"修复"它，改了底部会留黑边
- 电压量程自动识别是启发式（哪路通道变化大显示哪路），边界情况不够严谨
- F103 没有硬件浮点，浮点运算占用偏高
